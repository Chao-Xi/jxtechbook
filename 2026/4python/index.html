    0. Virtual Environment

    Create

    python3 -m venv venv

    Activate — Linux/macOS

    source venv/bin/activate

    Activate — Windows CMD

    venv\Scripts\activate

    Activate — Windows PowerShell

    .\venv\Scripts\Activate.ps1

    Deactivate

    deactivate

    Interview Point

    Why use a virtual environment?

    To isolate Python dependencies between projects and avoid version conflicts.

    1. File Operations

    Read a file

    with open("file.txt", "r") as file:
    content = file.read()

print(content)

    Read line by line

    with open("file.txt", "r") as file:
    for line in file:
        print(line.strip())

    Interview tip:

    For large files, prefer iterating line-by-line rather than read() because it avoids loading the entire file into memory.

    Write a file

    with open("output.txt", "w") as file:
    file.write("Hello, DevOps!")

    Append

    with open("output.txt", "a") as file:
    file.write("\nNew line")

    Common modes

    Mode Meaning
    r Read
    w Write / overwrite
    a Append
    r+ Read + write
    rb Read binary
    wb Write binary

    2. Environment Variables

    Very important for DevOps.

    Read

    import os

db_user = os.getenv("DB_USER")
print(db_user)

    Better:

    db_user = os.getenv("DB_USER", "default_user")

    This provides a default value.

    Set

    import os

os.environ["APP_ENV"] = "production"

    DevOps Best Practice

    Don't do:

    PASSWORD = "MyPassword123"

    Instead:

    password = os.getenv("DB_PASSWORD")

    3. Subprocess Management

    One of the most important Python DevOps topics.

    Execute command

    import subprocess

result = subprocess.run(
    ["ls", "-l"],
    capture_output=True,
    text=True
)

print(result.stdout)

    Check return code

    result = subprocess.run(
    ["ls", "-l"],
    capture_output=True,
    text=True
)

if result.returncode == 0:
    print("Command succeeded")
else:
    print("Command failed")
    print(result.stderr)

    Fail automatically

    subprocess.run(
    ["ls", "-l"],
    check=True
)

    If the command fails, Python raises subprocess.CalledProcessError.

    Interview Question

    Q: Why use subprocess.run() instead of os.system()?

    Good answer:

    subprocess.run() provides better control over arguments, stdout, stderr, return codes, timeouts and error handling. It is generally preferred for automation scripts.

    30. Rate-Limited APIs

    原始代码：

    while True:
    response = requests.get(url)

    if response.status_code == 200:
        print(response.json())
        break

    elif response.status_code == 429:
        time.sleep(60)

    else:
        print("Error:", response.status_code)
        break

    可以改得更 production-ready。

    Exponential Backoff

    import time
import requests

url = "https://api.example.com/data"

max_retries = 5

for attempt in range(max_retries):
    response = requests.get(url, timeout=10)

    if response.status_code == 200:
        print(response.json())
        break

    if response.status_code == 429:
        delay = 2 ** attempt
        time.sleep(delay)
        continue

    response.raise_for_status()

    例如：

    Attempt 1 → 1 sec
Attempt 2 → 2 sec
Attempt 3 → 4 sec
Attempt 4 → 8 sec
Attempt 5 → 16 sec

    更好的答案

    生产环境还可以考虑：

    Exponential Backoff
+
Jitter
+
Retry Limit
+
Retryable Status Codes
+
Timeout

    面试问题

    Why should we use exponential backoff instead of retrying immediately?

    因为立即 retry 可能：

    Server overloaded
      ↓
Client retries
      ↓
More load
      ↓
Server gets worse
      ↓
More retries

    形成 retry storm。
